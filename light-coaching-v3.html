시작 전
코칭 시작 전에 꼭 읽어주세요 👋
2주 동안 무엇을 배우는지, 어떤 흐름으로 진행되는지, 슬랙은 어떻게 쓰는지 안내합니다.

이 과정의 필수 완성 목표는 ‘업무 대시보드 MVP’입니다.
2주 동안 업무 입력, 완료 체크, 업무일지 생성, 기본 저장 기능이 작동하는 첫 번째 버전을 완성합니다.
캘린더와 통계 기능은 모든 수강생의 필수 과제가 아니라, 기본 기능을 완성한 뒤 더 확장해보고 싶은 분들을 위한 선택 기능으로 제공합니다.

중요한 것은 모든 기능을 다 넣는 것이 아니라, 문제정의에서 출발해 실제로 작동하는 첫 버전을 완성해보는 것입니다.
기능이 적더라도 사용 흐름이 명확하고, 내가 왜 이 기능을 만들었는지 설명할 수 있다면 이 과정의 핵심 목표는 달성한 것입니다.
필수 MVP 기능 vs 선택 확장 기능

필수 MVP 기능:

  • 업무 입력
  • 업무 수정/삭제
  • 완료 체크
  • 완료된 업무 목록 확인
  • 완료된 업무를 바탕으로 업무일지 생성
  • 새로고침해도 기록이 유지되는 기본 저장 기능
  • 오늘 업무 / 완료 업무 / 업무일지 영역이 구분된 기본 대시보드 화면

선택 확장 기능:

  • 날짜별 기록을 보는 캘린더
  • 완료율, 카테고리별 업무량, 주간 업무량을 보는 통계
  • Ollama 또는 AI 모델을 활용한 업무일지 문장 고도화
  • 브랜드 컬러, 카드 스타일, 레이아웃 디자인 커스텀

Ollama가 뭔가요?

Ollama는 오픈소스 AI 모델을 내 컴퓨터에서 실행할 수 있게 해주는 도구입니다.

ChatGPT나 Claude는 인터넷을 통해 외부 서버에 요청합니다. Ollama는 반대로 내 컴퓨터 안에서 AI가 돌아갑니다. 인터넷 없어도 되고, API 비용도 없고, 회사 업무 데이터가 외부로 나가지 않아요.

왜 이걸 쓰나요?

Ollama (로컬)
✅ API 키 불필요

1주차 · STEP 1 ⏱ 약 20분
리서치 — 내 업무 기록 방식 돌아보기
앱을 만들기 전에, 지금 내가 (그리고 내 주변 사람들이) 업무를 어떻게 기록하고 있는지 먼저 관찰합니다. UX는 항상 '지금 현실'에서 출발합니다.
왜 리서치부터 시작하나요?

앱을 만들기 전에 사람들이 실제로 어떻게 살고 있는지를 먼저 보는 것 — 이게 UX 리서치의 핵심입니다.

내 불편함을 기반으로 만들되, 나만의 불편인지 다른 사람도 같은 문제를 겪는지 확인해야 "팔리는 앱"이 됩니다. 그래서 짧은 리서치가 필요합니다.

파트 A — 나 자신 관찰 (5분)
📝
정답이 없습니다. 노션, 메모장, 종이에 솔직하게 적어보세요. 이 답변들이 STEP 2 문제정의의 핵심 재료가 됩니다.
Q1
지금 업무를 어떻게 기록하고 있나요?
사용하는 도구와 방식을 구체적으로 적어보세요.
예시 → "카카오톡 나에게 보내기로 대충 남겨두고, 퇴근 전에 노션에 옮기려 하는데 자주 까먹어요."
Q2
하루 업무를 기록할 때 가장 귀찮거나 막히는 순간은 언제인가요?
구체적인 상황을 떠올려 적어보세요.
예시 → "퇴근 직전에 오늘 뭐 했는지 기억이 안 나서 업무일지를 못 씁니다."
Q3
지금 방식에서 가장 아쉬운 점이 뭔가요?
도구 문제인가요? 습관 문제인가요? 아니면 구조 자체가 없는 건가요?
예시 → "기록은 하는데 나중에 찾아보기가 너무 불편해요."
Q4
이상적으로 업무 기록이 어떻게 돌아가면 좋겠나요?
지금 없는 것, 있으면 좋겠다고 생각한 것을 자유롭게 적어보세요.
예시 → "완료 체크만 하면 업무일지가 자동으로 만들어지면 제일 좋겠어요."
파트 B — 주변 2~3명에게 물어보기 (10분)
왜 주변 사람에게 물어봐야 하나요?
내 불편함은 "내 불편함"일 수 있습니다. 다른 사람도 같은 문제를 겪는다면 — 그게 진짜 문제입니다. 직장 동료, 프리랜서 지인, 팀원 누구든 2~3명에게 물어보세요. 5분 대화면 충분합니다.
인터뷰
물어볼 질문 3가지 (복붙해서 사용하세요)
1. 지금 업무 기록을 어떻게 하고 있어요?
2. 업무일지 쓸 때 제일 불편한 점이 뭐예요?
3. 이런 앱이 있으면 쓸 것 같아요? → WorkLog 한 줄 설명 후
들은 내용을 메모해두세요. 나와 비슷한 패턴이 나오면 문제가 검증된 것입니다.
파트 C — VOC(고객의 소리) 수집 (선택, 더 깊게 리서치하고 싶다면)
VOC(Voice of Customer)란?
고객이 직접 남긴 말을 수집하는 것입니다. 인터뷰는 내가 질문을 던지지만, VOC는 이미 어딘가에 적혀 있는 불만과 요구를 찾아내는 방식입니다.
VOC
어디서 VOC를 수집하나요?
📱 앱스토어 리뷰 — 경쟁 서비스(Notion, Todoist 등)의 1~3점 리뷰. "이런 게 불편해요"가 핵심 재료입니다.
💬 커뮤니티 — 직장인 커뮤니티(블라인드, 잡플래닛), 개발자 커뮤니티에서 "업무일지" 검색.
🔍 SNS 검색 — 트위터/X, 인스타그램에서 "#업무일지 불편" "#업무기록" 검색.
📊 설문 — Google Form으로 3~5문항 설문 만들어서 카톡으로 배포.
정리
수집한 VOC 정리 방법
수집한 말들을 그대로 메모해두세요. 그 다음 비슷한 내용끼리 묶어보세요.
예: "매일 쓰기 귀찮아요" / "뭘 적어야 할지 모르겠어요" / "쓰고 나서 활용을 못 해요" → 공통 패턴: 진입 장벽이 높음
리서치 후 정리할 것

파트 A + B + C 내용을 보고, 아래 두 가지를 메모해두세요.

공통으로 나온 불편함 — 나 혼자만의 문제가 아닌 것. 이게 문제정의의 핵심이 됩니다.

나만 겪는 불편함 — 이건 내 앱의 개성이 될 수 있습니다.

문제정의
이 단계가 2주 코칭에서 가장 중요합니다. 문제정의가 흔들리면 이후 모든 단계가 흔들립니다. 충분히 시간을 쓰세요.
왜 문제정의가 가장 중요한가요?

잘못된 문제를 해결하는 앱은 아무리 잘 만들어도 아무도 쓰지 않습니다.

문제정의는 앱의 나침반입니다. 이 나침반이 정확하면 이후 기능 우선순위, 화면 구조, 바이브코딩 프롬프트까지 모든 결정이 쉬워집니다. 반대로 나침반이 잘못되면 기능을 다 만들어도 "근데 이게 진짜 문제를 해결하나?"라는 의심이 생깁니다.

좋은 문제정의 vs 나쁜 문제정의
❌ 나쁜 문제정의
"사람들이 업무 관리 앱이 필요하다."

→ 누가? 언제? 왜? 가 없음
→ 솔루션(앱)이 문제에 들어와 있음
→ 이 문장으로는 어떤 기능도 정당화 불가
✅ 좋은 문제정의
"직장인은 퇴근 전 업무일지를 못 쓰는 문제를 겪으며, 이유는 오늘 뭘 했는지 기억에 의존해야 하기 때문이다."

→ 누가/언제/무엇/왜가 명확
→ 해결책 없이 문제만 정의
→ 이 문장에서 Must 기능이 보임

💡 STEP 3의 사용자 흐름을 보면서 어떤 기능이 진짜 필요한지 판단하세요.
기능 우선순위 결정
모든 기능을 다 넣으려 하면 아무것도 완성되지 않습니다. 첫 버전에 꼭 필요한 것만 남기는 연습입니다.
Must / Later / Out 기준
M
Must — 첫 버전에 반드시 있어야 함
없으면 핵심 문제가 해결되지 않는 기능. 이게 없으면 앱을 쓸 이유가 없는 것들.
L
Later — 있으면 좋지만 나중에
없어도 핵심 경험은 가능. MVP 이후 확장할 때 추가.
O
Out — 지금은 넣지 않음
넣으면 복잡해지거나 범위를 벗어남. 다음 버전 또는 프리미엄 코칭에서.
어떤 기능을 Must로 넣어야 할까요? — 판단 기준
Must 판단 3가지 질문
아래 세 가지 중 하나라도 "예"라면 Must입니다.
판단 질문 설명 WorkLog 예시
이 기능 없이 핵심 문제가 해결되나요? 문제정의에서 정의한 문제를 이 기능 없이 해결할 수 있다면 Later 또는 Out입니다. 업무 입력 없으면 → 해결 불가 → Must
사용자 흐름에서 이 기능을 건너뛸 수 있나요? STEP 3에서 그린 흐름에서 이 기능이 빠져도 흐름이 완성된다면 Later입니다. 캘린더 없어도 흐름 완성 → Later
이 기능을 만드는 데 2주가 걸릴 것 같나요? 공수가 너무 크다면 Out. 2주 안에 작동하는 형태로 만들 수 있어야 Must입니다. 팀 공유 기능 → 복잡 → Out
흔한 실수 — 이런 기능은 Must가 아닙니다

로그인/회원가입 — 혼자 쓰는 앱이라면 로그인 없어도 됩니다. localStorage로 충분해요.

알림 기능 — 있으면 좋지만, 없어도 핵심 경험은 가능합니다.

"예쁜" UI — 기능이 작동하는 게 먼저입니다. 디자인은 나중입니다.

공유/내보내기 — 복사하기 버튼 하나로 대체 가능한 경우가 많습니다.

STEP 8. 업무일지 생성 기능 만들기
이 단계가 WorkLog의 핵심 가치입니다. 완료된 업무를 AI가 읽고 업무일지로 만들어줍니다. 그리고 API 비용 없이 내 컴퓨터에서만 돌아가는 로컬 AI를 연결합니다.
2단계로 진행합니다
9-A 먼저
기본 업무일지 생성
완료된 업무를 포맷팅해서 업무일지 텍스트 만들기. AI 없이 먼저 작동시킵니다.
9-B 이어서
Ollama AI 연동

STEP 9-A — 기본 업무일지 생성
우측 패널에 업무일지 자동 생성 기능을 추가해줘. 동작 방식: - 오늘 완료된 업무 목록을 가져온다 - 아래 형태로 업무일지 텍스트를 자동 생성한다 [YYYY년 MM월 DD일 업무일지] • 업무명1 (카테고리) • 업무명2 (카테고리) 총 N건 완료 - 완료 업무 없으면 "오늘 완료한 업무가 여기에 자동으로 요약됩니다." 표시 - 우측 상단에 '복사하기' 버튼 추가 → 클릭 시 클립보드 복사 - 업무 완료할 때마다 실시간 업데이트
9-B — Ollama AI 연동 (이게 핵심입니다!)
왜 Ollama를 연결하나요?
지금까지 업무일지는 완료된 항목을 단순 나열하는 수준입니다. Ollama를 연결하면 AI가 업무 내용을 분석해서 "오늘 UI 개선 작업과 API 연동 작업을 완료하여 프로젝트 진행률을 높였습니다." 같은 실제 문장을 생성합니다. API 키도, 인터넷도, 요금도 필요 없습니다.
사전 확인
Ollama가 실행 중인지 확인하세요
터미널에서 ollama list 실행 → gemma2:2b가 보여야 합니다. 설치가 안 됐으면 STEP 7로 돌아가세요.
STEP 9-B — Ollama 연동 프롬프트
업무일지 생성 기능에 Ollama 로컬 AI를 연동해줘. Ollama 연동 방식: - Ollama는 로컬에서 http://localhost:11434 로 실행 중 - 사용할 모델: gemma2:2b - API 엔드포인트: POST http://localhost:11434/api/generate 동작 흐름: 1. 완료된 업무 목록을 아래 프롬프트와 함께 Ollama에 전달한다 2. Ollama가 생성한 업무일지 텍스트를 우측 패널에 표시한다 3. Ollama 요청 중에는 "AI가 업무일지를 작성 중입니다..." 로딩 표시 4. 오류 발생 시 기본 포맷팅 방식(9-A)으로 fallback Ollama에 보낼 프롬프트: "다음은 오늘 완료한 업무 목록입니다: {완료된 업무 목록} 이를 바탕으로 전문적인 업무일지 문단을 한국어로 3~5문장 작성해주세요. 형식: [날짜] 업무일지\n내용\n총 N건 완료" 주의사항: - CORS 문제가 발생하면 Next.js API Route를 통해 프록시 처리해줘 - Ollama가 응답하지 않으면 기본 포맷(9-A)으로 자동 전환
